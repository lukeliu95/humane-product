# 任务走查

测试集测的是功能对不对；任务走查测的是人能不能用。两样都要。

## 任务从哪来

从意图卡抄到 `docs/product/task-tests.md`：3～5 个验收任务（含主任务），再加两三个刁难任务（输错想改回来、做到一半被叫走、数据又长又乱）。每个任务写清起点、完成标志、步数上限。

## 第一遍：agent 走（预检）

用当前环境能用的浏览器工具（Claude Code 桌面版的内置浏览器、Chrome 扩展、Playwright 都行），扮成第一次用、最难伺候的那个真实用户：

- 只用屏幕上看得到的东西。不改网址、不看代码、不开开发者工具（下面的探针除外）。
- 计步：每次点击、每填一个输入框、每做一次选择，各算一步。滚动不算。
- 记下每个"犹豫点"：第一次用的人会停下来想的地方。图标没有字、两个按钮差不多、找不到入口、看不懂的词、不知道成功了没有。
- 每个关键页面执行一次 `scripts/dom_probe.js`，记下数字。两种执行法：把文件内容整个交给浏览器的 JS 执行工具（或 Playwright 的 `page.evaluate`）；或者页面和探针同源时，用 `<script>` 标签注入，再读 `window.__HUMANE_PROBE_RESULT`。要改上限时，先在页面里设 `window.__HUMANE_LIMITS = {primaryButtons: 1, defaultFilters: 3, helpParagraphs: 2}`。
- Claude Code 内置浏览器打不开本地文件页面来执行脚本：先起本地服务（项目的开发服务器，或 `python3 -m http.server`），用 localhost 地址打开。
- 截图只在任务完成和出问题时截，存到 `docs/product/checks/YYYY-MM-DD/`，写绝对路径。

一个任务过关 = 走得通 + 步数不超过上限 + 犹豫点里没有 P0、P1。

## 务实过滤

每个发现的问题先过一遍：
- 一般用户也会遇到 → 修
- 只有极端用户才会遇到 → 记下，不急着改
- 其实是"想要一个新功能" → 进 LEDGER"待议"，不直接做

没有这一步，会为了一个最挑剔的人把界面加得越来越复杂。

## 第二遍：真人走

能找到真人就做，5 分钟够了：
- 找一个目标用户，不是开发者自己。
- 只给任务卡（用界面的语言写，日语界面就给日语任务卡），不解释，不帮忙，不提示。
- 看他在哪里停下、说了什么，原话记下来。

找不到真人：负责人自己走一遍，结论写"未经真实用户验证"。agent 走过不等于用户验证过，两者不能混。

## 回归

每次改动后，全部任务再走一遍，不只走改过的那个。结果追加到 task-tests.md：

| 日期 | 任务 | 结果 | 步数/上限 | 犹豫点 | 谁走的 | 记录 |
|---|---|---|---|---|---|---|
| 2026-10-26 | T1 | 通过 | 4/5 | 无 | agent | checks/2026-10-26/ |

"谁走的"只写 agent、负责人、真实用户三种之一。
