# 边界怎么守

## 什么算"新增"

新的筛选条件、表单字段、菜单或导航项、设置项或开关、术语或状态名、页面、弹窗、通知、同一屏的第二个主按钮、新的外部服务。

## 规则

1. 意图卡写了的，做。
2. 没写的，不写代码。记进 LEDGER"待议"：想加什么、从哪冒出来的、不加会怎样。先用现有方式把任务做完，交付时列给负责人定。
3. 例外：修 bug 必需的、无障碍必需的（标签、焦点、对比度）不算新增。
4. 先复用再新增：已有的组件、页面、叫法能办到的，不另做一个。

## 上限

默认值在 LEDGER 的"上限"一节，项目可以改，改了写理由：

| 项 | 默认上限 |
|---|---|
| 一屏主按钮 | 1 个 |
| 默认显示的筛选条件 | 3 个，多的收进"更多条件"并默认收起 |
| 主任务步数 | 5 步（意图卡可以单独定） |

这三个数是草案，团队还没最终确认。

## 一次只改一类

一类 = 为同一个目的的改动，比如"改列表的排序"。混在一起的需求拆开：一类做完、check 过了，再做下一类。没过不叠加新改动。

## 每次改动前问三句

- 这次改动加不加东西？加的在意图卡里吗？
- 和 LEDGER 的否决记录、不做清单冲突吗？
- 叫法和术语表一致吗？

## 功能里用到模型时

- 换模型前后要能比较：准确、速度、花费
- 要有开关能退回旧的
- 用户界面上不出现模型名
