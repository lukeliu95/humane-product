# 意图卡：名刺管理（PC 网页 demo）

> 状态：已确认（2026-10-26，确认人：Luke）
> 相关文件：LEDGER.md、task-tests.md
> 标"推断"的是 agent 从需求和仓库里推出来的，请确认或改掉。
> 背景：humane-product skill 的第一次试跑。

## 1. 谁、在什么场景用

- 用户：日本企业的営業担当，一个人用
- 场景：办公室 PC 浏览器。展示会、拜访回来后集中登记当天拿到的名片（一次 3～20 张）；平时要联系某人时打开来找
- 他现在怎么做：纸名片夹、Excel 一行一人，或者 Sansan / Eight 这类服务。沿用的习惯：按公司找人、按读音排序、邮箱电话直接复制

## 2. 真实目的

- 表面需求："做一个名片管理工具 demo"
- 追问链：登记名片 → 之后做什么？→ 需要时找到这个人 → 发邮件、打电话 → 推进商谈
- 真实目的：交换过名片的人，要联系时几秒内找到，并且拿到能直接用的邮箱和电话
- 所以这次的做法：首页就是名片列表加一个搜索框，不做多条件筛选；点开一张就能复制邮箱、电话

## 3. 怎样算成功

- 主任务：把今天拿到的一张名片登记进去
- 步数上限：5
- 第一次用、不看说明能完成：是
- 验收任务：见 task-tests.md（T1～T6）

## 4. 真实样本

- 待取样本。demo 用 30 张左右的虚构名片（长短不一、有缺项、全角半角混着），界面和数据里标明虚构

## 5. 明确不做

| 不做什么 | 理由 |
|---|---|
| 拍照识别（自动读名片） | demo 没后端，要接视觉模型、要花钱；Luke 定只做手动录入 |
| 登录、多人共享、权限 | 一个人用的 demo |
| 设置页、主题切换、个人资料页 | 任务里用不到 |
| 仪表盘、统计图、"最近活动" | 任务里用不到 |
| 标签、分组、文件夹 | 搜索已能找到人；没人提 |
| 多条件筛选 | 一个搜索框覆盖公司名、姓名、读音、部署 |
| 导出（CSV / Excel） | 没人提，先记待议 |
| 和 CRM、邮件系统联动 | demo 范围外 |
| 引导教程弹窗、帮助浮窗 | 界面要做到不用教 |

## 6. 风险动作

| 动作 | 怎么确认 | 怎么撤回 |
|---|---|---|
| 删除名片 | 不弹确认框，删完底部提示「削除しました」 | 提示里带「元に戻す」，几秒内可撤回 |
| 发邮件 | 本工具不代发。点邮箱只是复制，或打开用户自己的邮件软件 | 不涉及 |

## 7. 界面语言和叫法

- 界面语言：日语（です・ます体）
- 叫法（写进 LEDGER 术语表）：名刺、氏名、フリガナ、会社名、部署、役職、メール、電話、携帯、住所、交換日、メモ

## 8. 要人判断的地方

- 已定：只做手动录入；首页以搜索找人为主，不加跟进状态
- 视觉风格是否和 GBase 现有产品对齐
- 产品名（暂用「名刺管理」）
